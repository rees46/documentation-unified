# Расширение "Недвижимость"

```
offer > realty
```

Нишевый алгоритм "Недвижимость" предназначен для товарных рекомендаций в области недвижимости. Основные отличия:

* Учитывает характеристики объектов (площадь, этаж).
* Учитывает тип сделки (продажа, аренда). 
* Учитывает тип недвижимости (жилая, коммерческая).

Для работы алгоритма вам необходимо передавать дополнительные параметры объектов:

* площадь;
* тип;
* вид сделки.

## Особенности

### Особенности цены объекта

В качестве цены объекта указывается стоимость за 1 квадратный метр.

### География

Географические привязки объектов указываются с помощью секции `locations`, описанной в основном документе о YML-файле. В записи `location` не нужно указывать цену объекта.

## Площадь объекта

```
offer > realty > space
```

Включает минимальное, максимальное или точное значение площади объекта. Площадь всегда указывается в квадратных метрах, даже если это земельный участок в 30 га.

Пример:

::: code-group
```XML [YML]
<offer ...>
    ...
    <realty>
        <space>
            <!-- Можно указывать минимальную и максимальную площадь для группы объектов или точную площадь для конкретного объекта -->
            <min>30</min>
            <max>100</max>
            <final>37</final>
        </space>
    </realty>
</offer>
```

```json [JSON API]
{
  "realty": {
    "space": {
      "min": 30,
      "max": 100,
      "final": 37
    }
  }
} 
```
:::


## Этаж

```
offer > realty > floor
```

Необязательный элемент `floor` указывает этаж и этажность объекта.

Пример:

::: code-group
```XML [YML]
<offer ...>
    ...
    <realty>
        <floor>
            <!-- Этаж, на котором находится объект -->
            <current>3</current>
            <!-- Всего этажей в здании -->
            <total>12</total>
        </floor>
    </realty>
</offer>
```

```json [JSON API]
{
  "realty": {
    "floor": {
      "current": 3,
      "total": 12
    }
  }
} 
```
:::


## Тип сделки

```
offer > realty > action
```

Обязательный параметр.

| Значение элемента | Расшифровка       |
|-------------------|-------------------|
| rent              | Объект в аренду   |
| sale              | Объект на продажу |

::: warning Важно
Если один и тот же объект и продается и сдается в аренду, в YML должно быть два объекта `offer` с разными ID.
:::

Пример:

::: code-group
```XML [YML]
<offer ...>
    ...
    <realty>
        <action>sale</action>
    </realty>
</offer>
```

```json [JSON API]
{
  "realty": {
    "action": "sale"
  }
} 
```
:::

## Тип недвижимости 

```
offer > realty > type
```

Обязательный параметр. Содержит тип недвижимости.

| Значение элемента | Расшифровка          |
|-------------------|----------------------|
| living            | Жилое помещение      |
| office            | Офис                 |
| warehouse         | Складское помещение  |
| land              | Земельный участок    |
| shop              | Магазин              |
| manufacturing     | Производство         |
| cafe              | Кафе, рестораны      |
| custom            | Свободное назначение |

Внутри самого тега может находиться атрибут `specific`, содержащий строковый код подтипа в системе наименований магазина (например, `coworking` для офиса, `apartment` для квартиры или `cottage` для загородного дома). Названия можно использовать произвольные, но объекты одного подтипа должны содержать одинаковое значение типа и подтипа.

::: code-group
```XML [YML]
<offer ...>
    ...
    <realty>
        <type>office</type>
    </realty>
</offer>
```

```json [JSON API]
{
  "realty": {
    "type": "office"
  }
} 
```
:::
